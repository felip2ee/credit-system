Steps usam checkbox (`- [ ]`).

**Goal:** A plataforma fica pronta para o primeiro deploy: backup em S3-compatível, migração fora do container do app, alertas por e-mail, retenção e direitos LGPD, e2e Playwright no CI e runbook de deploy.

**Architecture:** Infra: um serviço Swarm `migrate` one-shot roda `migrate.mjs`; o app espera o schema com `migrate.mjs --check` usando só `app_runtime`. O container de backup aponta o Restic para `s3:` com credenciais em segredos Docker. O `notifications_cron` observa as respostas do dispatch e do tick e o marcador do backup, e manda e-mail via `nodemailer`. Domínio: migration `023_lgpd_retention.sql` com funções `SECURITY DEFINER` de anonimização e varredura; camada `src/lib/lgpd/*` → ação `src/actions/lgpd.ts` → ficha do Titular; a varredura roda no tick do M6. Qualidade: Playwright com `webServer`, projeto `setup` (login + MFA, `storageState`), TOTP próprio, três specs, passo no job `test` do CI.

**Tech Stack:** Next.js 14.2, PostgreSQL 18 (RLS), node-postgres, zod 3, Vitest 4, `node --test`, Python `unittest`, Docker Swarm, Restic 0.18.1, nodemailer 10, `@playwright/test` 1.62.

**Spec:** `docs/superpowers/specs/2026-10-16-m7-producao-design.md`. Issues: #47, #48, #49, #50, #51, #52. Branch: `feature/m7-producao` a partir de `main`. **Aprovação:** as decisões D1–D9 da spec precisam do "sim" do usuário antes da onda 1.

## Decisões deste plano que completam a spec

1. **`--check` é um modo de `migrate.mjs`, não um script novo.** Mesma leitura de arquivos e de `schema_migrations`; sem lock, sem escrita. Sai `0` atual, `2` pendente, `1` erro (inclui tabela ausente).
2. **O alerta vive no cron runner, não no app.** O runner já vê o status de cada chamada; o app não ganha dependência de SMTP para alertar. O marcador de backup chega por volume read-only.
3. **A anonimização é uma função SQL por entidade; o TypeScript só traduz o retorno.** Os motivos `'ok' | 'not_found' | 'already_anonymized' | 'open_orders' | 'balance'` são a interface; a UI não decide regra.
4. **Exportação em TypeScript com a RLS da equipe.** Leituras normais no `withUserTransaction`; nenhuma função SQL nova para ler. Campos excluídos por nome (`auth_code`, `public_token`, `consent_ip`).
5. **O e2e é dono da sua semente.** `e2e/global-setup.ts` cria dados com prefixo `e2e-` e os remove no início da próxima execução. Não depende do `AUTH_E2E_*` do ambiente.
6. **CI em um job.** O e2e reaproveita o Postgres e o `build` do job `test`. Separar em job novo custaria um segundo build.

## Review Focus

1. App novo com schema velho — Task 1: `--check exits 2 when a migration is pending`, `entrypoint retries --check until exit 0`.
2. Chave S3 fora do segredo — Task 2: `s3 keys are docker secrets and never in env file`, `load_secrets exports aws keys from files and never echoes them`.
3. Anonimização fora do tenant ou com pedido aberto — Task 4: `another bureau gets not_found`, `anonymize refuses an open order`.
4. Exportação vazando segredo ou terceiro — Task 4: `export has no auth_code public_token consent_ip or other holder`.
5. Alerta em tempestade ou em silêncio — Task 3: `same key within 60 minutes sends nothing`, `missing OPS_ALERT_TO logs and sends nothing`, `transport failure is logged and does not stop the loop`.
6. Varredura apagando dado vivo — Task 4: `purge deletes expired technical rows and keeps fresh ones`.
