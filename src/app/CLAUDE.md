# app — Next.js App Router routes, layouts and route handlers

Route tree for the platform and CRM (Reino do Crédito), grouped as `(auth)`, `(dashboard)`, `(portal)`, `(superadmin)`, plus `api/`, `auth/`, `b/[slug]` and public `autorizacao-scr/[token]`. Security-sensitive: it is the session, role and redirect boundary.

## Responsibility

Belongs here: `layout.tsx`, `page.tsx` and `route.ts` files, `globals.css`, and colocated route tests (`api/health/health.test.ts`, `auth/callback/route.test.ts`). Pages compose UI and fetch data; they do not hold business logic or SQL. Reusable UI lives in `src/components`, queries and domain logic in `src/lib`, mutations in `src/actions`.

## Key patterns

- Role gating is done in group layouts. `(dashboard)/layout.tsx` calls `getRequiredSession()` and redirects a session error to `sessionErrorPath(err)`: `/mfa/setup`, `/change-password` or `/login`. It redirects `role === "client"` to `/portal`, and a superadmin without a support session to `/superadmin`.
- `(portal)/layout.tsx` is the inverse: any role other than `client` is redirected to `/`. `(superadmin)/layout.tsx` does the same for any role other than `superadmin`. Both use `sessionErrorPath` on a session error.
- `(auth)/change-password/layout.tsx` shows the page only to a user with the `must_change_password` flag. A session error with another code redirects through `sessionErrorPath`. A user without the flag is redirected to `/`.
- Pages are async Server Components that load data from `src/lib/*/queries` (e.g. `listHolders` in `(dashboard)/holders/page.tsx`) and use `PageHeader` and `components/ui` primitives.
- Route handlers return plain `Response` objects: 401 for no session, 403 when `hasPermission(session, "consultations:read")` fails (`consultations/[id]/pdf/route.ts`).
- `dossiers/[id]/pdf/route.ts` checks `consultations:read` the same way before it renders the PDF.
- Redirect targets go through `safeRedirectPath` (`auth/callback/route.ts`, tested for off-origin URLs).
- Public token page `autorizacao-scr/[token]/page.tsx` exports `metadata` and calls `notFound()` on an unknown token.

## Local conventions

- Route segment names are English (`holders`, `dossiers`, `consultations`), except the Portuguese public/portal paths (`autorizacao-scr`).
- User-facing strings are pt-BR; the root layout sets `<html lang="pt-BR">`.
- Routing middleware is `src/middleware.ts` (Next 14), not `proxy.ts`; keep it out of `app/`.
- `/change-password` is not a public path in the middleware: it needs the session cookie.
- Client-side role redirects are not enough: re-check the session in each handler or page.
