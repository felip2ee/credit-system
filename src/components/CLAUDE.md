# components — React UI layer: shadcn primitives plus per-feature components

Presentation layer of the Next.js 14 App Router app. Pages in `src/app/` compose these components; data and mutations live elsewhere.

## Responsibility

Belongs here: shadcn primitives in `ui/` (`button.tsx`, `badge.tsx`, `card.tsx`, `table.tsx`, `input.tsx`, `label.tsx`) and feature folders (`holders/`, `dossiers/`, `consultations/`, `scr/`, `reports/`, `settings/`, `auth/`, `superadmin/`, `layout/`, `shared/`, `providers/`). Forms, filters, status badges, charts and buttons that trigger actions belong here. Does NOT belong: SQL or business rules (`src/lib/<domain>/queries.ts`), Server Actions (`src/actions/`), zod schemas (`src/lib/validators/`), shared types and labels (`src/types/`).

## Key patterns

- Forms: `"use client"` + `useForm` with `zodResolver(holderFormSchema)` in `holders/holder-form.tsx`. Submit runs `startTransition` over a Server Action, then `router.push` and `router.refresh()`.
- Action result is `{ error, id? }`: `HolderForm` keeps `serverError` in state and renders it as `<p className="text-sm text-destructive">`.
- Filters (`holders/holders-filters.tsx`) keep state in the URL with `useSearchParams` and `useRouter`.
- Status badges (`consultations/query-status-badge.tsx`) are server components. They render `StatusBadge` (`ui/status-badge.tsx`) with the tone and label from `statusInfo(domain, status, audience)` in `@/lib/ui/status`, the single status vocabulary. Alerts use `StatusBanner`; action notices use `toast` (`<Toaster />` is mounted in the dashboard and superadmin layouts).
- `ui/` follows shadcn: `cva` variants, `React.forwardRef`, `cn()` from `@/lib/utils`, `asChild` via Radix `Slot` (`ui/button.tsx`). Config in `components.json` (style `default`, base color `slate`, lucide icons, `rsc: true`).
- `providers/query-provider.tsx` is the only `QueryClient` (staleTime 60s, `retry: 1`); no component here calls `useQuery`.

## Applied rules

Rules active in this directory — read them before touching code here:

- @.claude/rules/react/coding-standards.md — Named exports (default only for pages), `<Name>Props` interface, stable keys, logic in `use<Name>` hooks, aria-label or visible text on interactive elements.
- @.claude/rules/typescript/coding-standards.md — No `any`; `@/` alias; explicit return types on public functions; split files over 350 LOC (several forms are 10-13 KB).
- @.claude/rules/05-testing.md — Test components only for conditional rendering, form validation, state logic or a11y behavior. Presentational UI gets no test.

## Local conventions

- File names are kebab-case, one exported PascalCase component per file, named export (`HolderForm`, `PageHeader`); props typed as `<Name>Props` or inline.
- Add `"use client"` only when the component uses hooks or handlers. Badges, `page-header.tsx`, `topbar.tsx` and charts in `reports/` stay server components.
- Add new shadcn primitives under `ui/` (`@/components/ui`); do not hand-roll a button or input in feature code.
- UI text is pt-BR (e.g. "Salvando..."); identifiers stay in English.
- Only `dossiers/filters.test.ts` exists under `src/components`; cover other logic in `src/lib` or `e2e/`.
