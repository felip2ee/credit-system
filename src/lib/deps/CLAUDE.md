# deps — DEPS Mix V3 credit-bureau client and response adapter

Server-only integration with the deps.com.br bureau. Security-sensitive: it reads bureau credentials and handles personal data (CPF/CNPJ).

## Responsibility

Belongs here: the HTTP client (`client.ts`, `real.ts`), the raw-payload-to-canonical adapter (`adapter.ts`), typed errors (`errors.ts`), product-name constants (`products.ts`) and recorded payloads in `__fixtures__/`. Does NOT belong here: persistence of consultations or SCR authorizations (`src/lib/scr/queries.ts`, `src/lib/consultations/`), shared types (`src/types/deps.ts`, `src/types/bureau.ts`), UI. `scr-auth.ts` is only a re-export shim of `@/lib/scr/queries`.

## Key patterns

- `getDepsClient()` in `client.ts` is the single entry point: caches one client, reads `DEPS_API_*` env, throws if credentials are missing. There is no mock fallback.
- `real.ts` caches the login session in a module variable, renews 60 s before expiry, and retries once on HTTP 401 (`postWithAuth`).
- `adapt(body: unknown, ctx)` in `adapter.ts` is the one trust boundary. It returns `AdaptResult` (`{ ok: true, value }` or `{ ok: false, version: ADAPTER_VERSION, errors }`) and never throws on bad payloads.
- Identity (name + document) is validated with zod and fails closed. Unknown/additive fields are ignored and not copied to the canonical result. Money is stored as integer cents (`cents()`).
- `AdapterError` carries a JSON `path` and code, never a value from the payload (asserted in `adapter.test.ts`).
- HTTP 400 on a consult means SCR authorization pending: `DepsScrPendingError`, handled as "pending", not as a failure.

## Local conventions

- Add a new bureau variant by dropping a payload in `__fixtures__/` (`pf-current`, `pf-legacy`, `pj-current`, `pj-legacy`) and a case in `adapter.test.ts`.
- Product names come only from `products.ts` (`DEPS_PRODUCT_PF`, `DEPS_PRODUCT_PJ`); do not repeat the literals.
- Server-only: never import this directory from client components.
- Comments here are pt-BR; the adapter header comments are English.
