# db — migration runner and dev-only database reset scripts

Node ESM scripts (`.mjs`) that apply `db/migrations` and rebuild a local database. They run with the owner role and can destroy data, so they are security-sensitive.

## Responsibility

Holds `migrate.mjs` (load, checksum-verify and apply migrations), `reset.mjs` (drop and recreate `public`, then migrate) and their `node --test` files. It does NOT hold the SQL (`db/migrations/`) or runtime DB access (`src/lib/db/`).

## Key patterns

- `migrate(connectionString = process.env.DATABASE_OWNER_URL)` takes `pg_advisory_lock(hashtext('credit-system-migrate'))`, creates `schema_migrations` if needed, and applies each pending file in its own begin/commit with rollback on error.
- `loadMigrations` and `pendingMigrations` are pure and exported so tests can use temp directories; `pendingMigrations` throws `checksum mismatch for migration <file>` or `applied migration <file> is missing from disk`.
- `assertResettable(connectionString, env)` refuses `NODE_ENV=production`, a missing URL, a URL without an explicit host, and any host (including `?host=` / `?hostaddr=`) that is not `localhost`, `127.0.0.1`, `::1` or a socket path.
- `assertDevDatabase(client)` refuses any database whose `app.env` setting is not `dev`. Set it once with `ALTER DATABASE <name> SET app.env = 'dev';`.
- `reset` runs `assertResettable` before it connects, then `assertDevDatabase`. It drops and recreates `public` in one transaction (owner set to `pg_database_owner`), then calls `migrate`.
- Both scripts run only when they are the entry file (`realpathSync(process.argv[1]) === fileURLToPath(import.meta.url)`) so tests can import them; they call `hydrateSecretEnv` from `src/lib/runtime-secrets.mjs`.

## Applied rules

Rules active in this directory — read them before touching code here:

- @.claude/rules/06-security.md — Least privilege, no secrets in logs. Here: the owner URL is never printed; destructive commands must have guards.
- @.claude/rules/ecc/common/security.md — Secrets from env only. Here: use `DATABASE_OWNER_URL`, never a literal.
- @.claude/rules/05-testing.md — Test branches with stakes. Here: every guard in `assertResettable` and every error in `pendingMigrations` has a test; no real DB in script tests.

## Local conventions

- Tests use `node --test` with `node:assert/strict`, named `*.test.mjs` beside the script.
- Export pure functions and keep side effects behind the entry-file check.
- Print errors as `error.message` and set `process.exitCode = 1`; do not call `process.exit`.
- Any new destructive script must reuse the `assertResettable` guard and the dev marker check before it drops anything.
